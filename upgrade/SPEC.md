# ZZZ 自动升级脚本：需求和安全规则

用户 2026-11-21 选择"写游戏升级脚本"：在游戏里自动完成代理人培养，省掉手动升级后重新截图。
main 写需求，fork 在游戏里开发和测试。

## 要做的事（按顺序交付，每一阶段测通再做下一阶段）

1. **代理人等级和突破**：把指定代理人升到目标等级，到整十级时自动突破。
2. **技能**：把 5 个技能分别升到目标等级（普攻 / 闪避 / 支援 / 特殊技 / 连携技）。
3. **核心技**：升到目标级（A–F）。
4. **音擎**：把代理人装备的音擎升到目标等级并突破。

驱动盘不在这次范围内。

## 用法

```
python upgrade.py --agent 简 --level 60 --skills 10,8,8,10,10 --core 6 --engine 60          # 默认只演练
python upgrade.py --agent 简 --level 60 --apply                                             # 真的升级
python upgrade.py --plan <仓库>\upgrade\plan.json --apply                       # 按清单批量
```

- 只写了的项目才动，没写的不碰。
- 目标低于当前等级时跳过，不降级。

## 安全规则（必须做到）

1. **默认演练**：不加 `--apply` 时只导航、截图、读数，不点任何会花材料或丁尼的按钮，最后打印"会花多少"。
2. **开始前检查**：
   - 游戏窗口必须是 1920×1080，否则直接退出并提示改分辨率。
   - 没有别的 OneDragon 运行在跑（`/game/status` 是 idle，log.txt 最近 30 秒没在更新）。
   - 游戏在大世界或已知界面，不在战斗中。
3. **每一步先确认画面再点**：点击前用 OCR 确认当前是预期界面、代理人名字对得上、按钮文字对得上（比如"升级""突破""确认"）。对不上就停下，截图保存，退出。不要猜坐标连点。
4. **每次花费前后都读数**：读当前等级/技能等级和丁尼，点完后再读一次，确认变化正确。数字不对就立刻停。
5. **单个代理人上限**：一次运行最多处理清单里的代理人，每个代理人每一项最多尝试到目标为止；出现两次连续失败就停。
6. **材料不够就停**：游戏提示材料或丁尼不足时，记录下来，跳过这一项，不去合成、不去商店买、不用菲林。
7. **不碰的东西**：不合成材料、不分解、不领取、不改装备、不碰驱动盘、不花菲林或任何付费货币。
8. **随时可停**：按 F10 或 Ctrl+C 能停，停下后把游戏退回大世界。
9. **日志**：每一步写到 `<仓库>\upgrade\logs\YYYY-MM-DD_HHMM.log`，关键步骤截图放同名文件夹。

## 输出（给 main 同步数据库用）

运行结束写 `<仓库>\upgrade\results\YYYY-MM-DD_HHMM.json`：

```json
{
  "started_at": "...", "finished_at": "...", "applied": true,
  "agents": [{
    "id": "jane_doe", "name_cn": "简",
    "before": {"lv": 60, "sk": [5,4,3,11,12], "core": 4, "wl": 40},
    "after":  {"lv": 60, "sk": [10,8,8,11,12], "core": 6, "wl": 60},
    "steps": [{"what": "技能 普攻 5→6", "ok": true}],
    "stopped_reason": null
  }],
  "dennies_before": 508970, "dennies_after": 123456,
  "skipped": [{"what": "核心技 E→F", "reason": "高维数据不足"}]
}
```

技能等级记游戏里显示的数字（含影画加成），并注明影画，main 会自己换算。

## 技能升级的操作流程（用户 2026-11-21 定的）

1. 按 `C` 键（代理人快捷键）。
2. 进入代理人列表后，识别角色头像图片，确认是清单里的那个角色。
3. 点「技能」。
4. 点要强化的那个技能。
5. 进入二级界面，点「确认」。**如果材料不够，就把还缺的材料写进刷取队列**（见下），这一步记为 skipped，继续下一步。

## 刷取队列 queue.json（脚本写入，每日推送读取）

文件：`<仓库>\daily\queue.json`。升级时游戏提示材料或丁尼不足，就把缺的部分追加进去：

```json
{"items": [
  {"item": "特化物理芯片", "need": 5, "for": "简 闪避 7→8", "added_at": "2026-11-21T13:40:00-08:00"},
  {"item": "丁尼", "need": 45000, "for": "简 闪避 7→8", "added_at": "2026-11-21T13:40:00-08:00"}
]}
```

- `need` 是这一步总共要的数量（看二级界面上写的消耗），不是差额；差额由每日推送按背包算。
- 同一个 `for` 已经在队列里就不要重复加。
- 每日推送（23:00 前）把队列里的材料换算成副本，排在最前面刷；背包够了就自动从队列删掉。
- 恶名狩猎材料和「仓鼠笼」访问器不能用电量刷，也照样写进队列，推送会提示但不排本。

## 升级清单 plan.json（main 生成，脚本执行）

用户 2026-11-21 定的目标："让你自动升级，同时升级到多少你要去网上学习找到最优解，合理调配资源"。
所以升到多少由 main 决定：main 查攻略定优先级，按现有背包算出"现在就够材料的升级步骤"，写成 plan.json，用户确认后脚本按顺序执行。

```json
{
  "generated_at": "2026-11-21T13:00:00-08:00",
  "approved_by_user": true,
  "approved_note": "用户在 main 里确认的原话",
  "steps": [
    {"order": 1, "agent": "jane_doe", "name_cn": "简", "what": "skill", "skill": "特殊技",
     "from": 11, "to": 12, "display_from": 11, "display_to": 12,
     "cost": {"特化物理芯片": 15, "丁尼": 135000, "「仓鼠笼」访问器": 1}},
    {"order": 2, "agent": "jane_doe", "name_cn": "简", "what": "core", "from": 4, "to": 5},
    {"order": 3, "agent": "lycaon", "name_cn": "莱卡恩", "what": "level", "from": 55, "to": 60},
    {"order": 4, "agent": "jane_doe", "name_cn": "简", "what": "engine", "from": 40, "to": 50}
  ],
  "budget_after": {"丁尼": 12345}
}
```

- `what`：`level`（含突破）/ `skill` / `core`（0–6，6=F）/ `engine`（代理人当前装备的音擎）。
- 技能等级：`from`/`to` 是去掉影画加成的基础等级，`display_from`/`display_to` 是游戏里显示的数字。脚本按 display 核对画面。
- **执行规则**：
  1. `--apply` 时必须 `approved_by_user` 为 true，否则只演练。
  2. 严格按 `order` 执行。每一步先读游戏里的当前值，和 `from` 对不上就跳过这一步并记录（说明账号数据变了），不要自己改目标。
  3. 只做清单里的步骤，不多升。
  4. 某一步失败或材料不够，跳过这一步，继续下一步；同一个代理人连续失败两次就跳过这个代理人。
  5. 结果文件里逐步记录 `ok / skipped / failed` 和原因，并记下最后的丁尼。

## 实现建议

- 用 OneDragon 后端（`http://127.0.0.1:23001`）。HTTP 接口没有点击，点击和按键走 MCP 工具 `click_game` / `key_tap`（venv 里的 `mcp` 2.0.0 客户端），读画面用 `analyze_screen` / `/game/analyze` 的 OCR 结果按文字定位按钮。
- 脚本放在 `<仓库>\upgrade\`，用 `<OneDragon>\.venv\Scripts\python.exe` 运行，不往 OneDragon 源码里加文件。
- 先拿一个代理人、一个最小步骤（比如某个技能升 1 级）做 `--apply` 测试，跟用户确认后再放开。
